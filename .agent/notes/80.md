**The port design is decided.** It is in the issue's Expected behavior and in this decisions
comment: https://github.com/TypeScriptSystemVerilog/TSSV/issues/80#issuecomment-6089711578
- `RO`: an input `<R>`. With `fields` (and no `constant`), one input `<R>_field<i>` per field,
  read back at its bit range. With `constant: true`, no port: it reads `reset`, or each field's
  `reset`. Add `constant?: boolean` to `Register`.
- `WO`: `<R>` is registered on a write to its address. `<R>_we` is a registered one-cycle pulse,
  high in the first cycle `<R>` shows the new value. That name collides with the internal decode
  `<R>_WE` (Verilator SIMILARNAME), so rename the internal `<R>_WE`/`<R>_RE` for all types.
- `RAM`/`ROM`: an outward `Memory` interface port named `<R>`
  (`addInterface(regName, new Memory({...}, 'outward'))`). `<R>.ADDR = regs.ADDR - base`, the
  byte offset inside the window. Enables, `DATA_WR` and `WSTRB` follow the `Memory` contract.
  A RAM read or write completes on `<R>.READY`. A ROM's `WE` is tied low and writes to it are
  dropped. A `width` that differs from `wordSize` throws, because `Memory`'s data width is
  `wordSize`.

## Assumptions

- `Memory`'s `WSTRB` is `ADDR_WIDTH/8` bits until #81 fixes it. `busAddressWidth` is typed as
  the literal `32`, so it is always 4 bits, which is wrong for a 64-bit `wordSize`. Pass
  `regs.WSTRB` through to `<R>.WSTRB` unchanged and leave the sizing to #81.
- `regs.READY` is tied to `1'b1` in `addReadMux()` at 47e1cf7, and `read_out` reads windows
  from the flat `<R>_wdata`/`<R>_rdata` ports. Check both before changing that code.
- `RegisterType.RO` has been an output port since commit 6d37281 (April 2024). ROM/RAM
  `<R>_rdata` were inputs until 4a3e066 (2024-08-02). That history is posted on the issue.

## Dead ends

None for #80 yet. From #79: `verilator --lint-only -Wall --top-module <block>` on a block with an
interface port still reports UNDRIVEN/UNUSED on the interface's signals. Only a wrapper top that
drives the interface removes them, as `lintTop()` in `ts/test/test_RegisterBlock_read.ts` does.
RAM/ROM `Memory` ports need the same treatment: the wrapper must also instantiate an interface
for each window and expose it.
