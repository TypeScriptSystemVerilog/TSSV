## Assumptions

- `Memory`'s `WSTRB` is `ADDR_WIDTH/8` bits until #81. The window passes `regs.WSTRB` through
  unchanged. The slave model writes bytes above the `WSTRB` width unconditionally, so the 64-bit
  tests work; #81 should remove that.
- An idle slave keeps `READY` high, including after reset. The block relies on it (§3 says so).
- `writeRALF()` writes a `RAM`/`ROM` as one register, not as a RALF `memory`. That is unchanged
  and outside this issue.

## Dead ends

- **Pass-through windows as the default**: rejected by the human on 2026-10-12. They exist only
  as the opt-in `registerRequest: false, registerResponse: false`.
- **Tying a ROM's write signals low**: replaced by the `rd_only` `Memory` type.
- **Leaving `type` out of the `Memory` SV name for `bidi`**: rejected; it is always included.
- **Making the block wait for `<R>.READY` before issuing**, so idle slaves need not hold `READY`
  high after reset: rejected, because it is itself a combinational path from slave back to slave.
- **Relative imports from `ts/test/` to `ts/test/models/`** fail under `node16` module
  resolution. Use `tssv/test/models/...` (the package's `./test/*` export).
- From #79: a module with an interface port can't be linted as the top. Use
  `ts/test/models/lintWrapper.ts`.
