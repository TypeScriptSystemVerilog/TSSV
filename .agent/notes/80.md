The port design is decided. See the issue's Expected behavior (edited 2026-10-09) and the
decisions comment: https://github.com/TypeScriptSystemVerilog/TSSV/issues/80#issuecomment-6089711578
In short:

- `RO`: an input `<R>`. With `fields` (and no `constant`), one input `<R>_field<i>` per field,
  read back at its bit range. With `constant: true`, no port, and it reads `reset` (or each
  field's `reset`). Add `constant?: boolean` to `Register`.
- `WO`: `<R>` is registered on a write to its address. `<R>_we` is a registered one-cycle pulse,
  high in the first cycle `<R>` shows the new value. That name collides with the internal decode
  `<R>_WE` (Verilator SIMILARNAME), so rename the internal `<R>_WE`/`<R>_RE` for all types.
- `RAM`/`ROM`: an outward `Memory` interface port named `<R>` (`addInterface(regName, new
  Memory({...}, 'outward'))`). `<R>.ADDR = regs.ADDR - base`, the byte offset inside the
  window. Enables, `DATA_WR` and `WSTRB` follow #116's contract. A RAM read or write completes
  on `<R>.READY`. A ROM's `WE` is tied low and writes to it are dropped. A `width` that differs
  from `wordSize` throws, because `Memory`'s data width is `wordSize`.

## Assumptions

- #116 lands a read path that holds `DATA_RD` after the `RE` pulse and selects `READY`/`DATA_RD`
  from the last access's target. If it doesn't, RAM/ROM here need that mechanism themselves.
- `Memory`'s `WSTRB` is `ADDR_WIDTH/8` bits (#81). `busAddressWidth` is typed as the literal `32`,
  so it is always 4 bits, which is wrong for a 64-bit `wordSize`. Pass `regs.WSTRB` through to
  `<R>.WSTRB` unchanged and leave the sizing to #81.
- `RegisterType.RO` has been an output port since commit 6d37281 (April 2024). ROM/RAM
  `<R>_rdata` were inputs until 4a3e066 (2024-08-02). That history is posted on the issue.
