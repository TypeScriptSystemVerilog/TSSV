   criterion 1), and agree it with the human. Starting proposal:
   - `RO`: an input `<R>`, the width of the register. With `constant: true`, there is no port and
     the register reads back its `reset`. With `fields`, it reads each field's `reset` at the
     field's bit range. A plain RO with a `reset` keeps its input, and `reset` only feeds RALF.
     Add `constant?: boolean` to the `Register` interface in `ts/src/core/Registers.ts`. Open
     question: does an RO with `fields` and no `constant` get one input per field, or one for
     the whole word? RO ignores `fields` today.
   - `WO`: an output `<R>`, registered when `<R>_WE` is high, with its reset from `reset`. Also
     an output write strobe that is high for one cycle per write to its address. Decide whether
     the strobe lines up with the new value, which means registering it too.
   - `RAM`: outputs for the address, `_re`, `_we`, `_wdata` and `_wstrb`. Inputs `_rdata` and
     `_ready`. Decide whether the address is the byte address or a word offset within the
     window, and whether outputs are combinational pass-through or registered. Today they are
     registered on `<R>_WE` only, which is wrong for reads. Also decide whether a RAM write waits
     for `_ready`: the read mux holds `regs.READY` at 1 except during RAM/ROM reads.
     `_wstrb` width overlaps #81.
   - `ROM`: outputs for the address and `_re`. Inputs `_rdata` and `_ready`.
   - **Naming.** RAM/ROM ports `<R>_re`/`<R>_we` differ only in case from the internal decodes
     `<R>_RE`/`<R>_WE`, and Verilator's `-Wall` reports this as SIMILARNAME. Rename one side so
     the lint is clean without waivers.

## Assumptions

- PR #94's branch won't change much before this lands. If it does, rebase this branch onto
  the new head of `origin/bug/79-registerblock-read-mux-decode`.
- `APB_to_Memory` (`ts/src/modules/APB_to_Memory/APB_to_Memory.ts`) drives `apb.PREADY` from the
  APB handshake and ignores `regs.READY`. So RAM/ROM `ready` only reaches a master on a direct
  Memory bus. This was true at 6ba565b.
- `RegisterType.RO` has been an output port since the first version that handled RO (commit
  6d37281, April 2024). It was never an input. ROM/RAM `<R>_rdata` were inputs until commit
  4a3e066 (2024-08-02) made them outputs. That history is posted on the issue.
