## Assumptions
- **The user's decisions, 2026-11-03.** They are now in the issue body.
  - LFSR payloads: a non-zero seed restarts the Lfsr at that seed, and seed 0 continues the
    sequence from the previous record.
  - Ties: a dependency per record (peer and count).
  - TrafficPhases goes to tier 1 in this issue.
- **Reloaded mode is built, not simulated, here.** tssv-noc#216 simulates it. The issue body
  says so.
- **The throttle's distribution** was checked by a 10^6-cycle Python model: each cycle is
  Bernoulli(rate/256); straight from injector to checker, the throughput is
  `1/(1/p_v + 1/p_r - 1)`. It wasn't measured in RTL simulation.
- **The record-stream names** (`inj_<port>`, `chk_<port>`, the memory paths, the checks) are
  defined in testbench.md, "Record streams". TSSV#200's template should adopt them.

## Dead ends
- **Binding an output the harness never reads.** check-harness lints -Wall, and only `err_*` is
  waived, so an unread output is a lint failure. That is why the checker's `count` exists only
  when it is tied, and TrafficPhases' `full_rate` only when a phase sets `fullRate`.
- **A phase timeout of 50 cycles per record of the whole run** was longer than SimTop's
  maxCycles, so a stuck phase failed as SimTop's timeout, not `progress`. The timeout is now 25
  cycles per record of a phase.
- **Tying the slice's `in_ready` port low doesn't block input.** The slice still captures, and
  the injector re-offers. To test `progress`, tie `out_valid` low instead.
- **Sharing the shift triples between Lfsr.ts and the model** would hide a wrong triple. The
  model has its own copy in `xorshift.ts`.
