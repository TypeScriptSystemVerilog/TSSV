API decisions made while building (not in the plan):
- The injector's memory mode parameter is `memory`, not `mode`. On the checker, `mode` is the
  check mode.
- Reloaded mode's record count is an input port named `records`.
- The checker's parameters are a union on `mode`. inOrder takes `file`/`records: number`;
  perSource takes `files`/`records: number[]`; cycleExact takes `rows`, `readyFile` and
  `file`.
- cycleExact reports per lane, `fail_valid` and `fail_record` (`firstCycleError()`).
- The detail lines:
  - `record %0d: got %h, expected %h`;
  - in perSource, `source %0d, record %0d: ...`;
  - for ties, `record %0d: arrived before peer %0d had delivered %0d records; it had %0d`.

## Assumptions
- **The user's decisions, 2026-11-03.** They are now in the issue body.
  - LFSR payloads: a non-zero seed restarts the Lfsr at that seed, and seed 0 continues the
    sequence from the previous record.
  - Ties: a dependency per record.
  - TrafficPhases goes to tier 1 in this issue.
- **Reloaded mode is not simulated in #198.** The injector and checker pass the memory mode
  through, and tssv-noc#216 simulates reloaded mode.
- **The throttle's distribution** (checked by a 10^6-cycle Python model on 2026-11-03):
  - each cycle is Bernoulli(rate/256);
  - two consecutive draws are exactly pairwise uniform;
  - straight from injector to checker, the throughput is `1/(1/p_v + 1/p_r - 1)`.
- **Record seeds should be mixed** (`mixSeed`, splitmix64-style). xorshift from a small seed
  stays sparse for several steps.
