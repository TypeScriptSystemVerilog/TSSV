What the branch does:

- `ts/src/core/VeribleSyntax.ts` (new) runs `verible-verilog-syntax --export_json --printtree`
  and has the tree helpers (`kids`, `child`, `findAll`, `identifier`, `sourceText`).
  `ts/src/core/SVModuleHeader.ts` used to hold this code; it now imports it, and re-exports
  `VeribleSyntaxOpts`, so `doc/reference/SVModuleHeader.md` doesn't change.
- `ts/src/core/AlwaysBody.ts`: `readAlwaysBody(where, header, body, reset?)` parses
  `module tssv_always_check;` + the header the builder writes + the body, and reads the tree:
  - every `kLPValue` is an assignment target; its parent's tag gives the kind
    (`kNonblockingAssignmentStatement` is `<=`, anything else is blocking);
  - a target's variables are the roots (`kLocalRoot`) of its `kReference` nodes; the search
    stops at each reference, so an index is a read, not a target;
  - locals are `kRegisterVariable` names in `kDataDeclaration` nodes, and variables declared in
    a `for` header (`kForInitialization` with a type);
  - `kTrailingAssign` marks an initializer; `kQualifierList` holds `automatic`;
  - reset branches: the if branch of an asserted condition (`!rst_n`, `~rst_n`, `rst_n == 1'b0`,
    ...), or the else branch of a deasserted one (`rst_n`). The condition's text is compared
    with spaces and parentheses removed;
  - a syntax error throws with the line and column in the body.
- `ts/src/core/Base.ts`: each builder builds `header`, calls `readAlwaysBody`, runs its checks,
  then appends `header + body`. That is the same string as before, so generated SV is unchanged.
  - COMB-3: `addCombAlways` rejects a nonblocking assignment. `<=` as a comparison is a
    `kBinaryExpression`, so it's accepted.
  - COMB-2: `addCombAlways`, `addSequentialAlways` and `addLatchAlways` reject a local declared
    with an initializer that isn't `automatic`. It is an error, not a warning.
  - SEQ-1: `addSequentialAlways` rejects a blocking write to anything the block doesn't declare.
  - SEQ-6: `addSequentialAlways` rejects a reset branch that reads a port or a non-constant
    signal. `addRegister` rejects a `resetVal` that isn't a `bigint`, at run time.
  - RST-2: `addRegister` and `addSequentialAlways` reject a reset whose kind (`isReset`) differs
    from the module's first one.

## Assumptions

- The reader still errs towards accepting where the tree doesn't say enough:
  - A reset branch inside a `case`, or under a condition other than the forms listed in State,
    isn't found, so SEQ-6 doesn't check it.
  - A target that has no plain reference, such as a streaming concatenation, names no variables,
    so SEQ-1 accepts it.
  - Locals are matched by name, not by scope: a local declared in one `begin` block counts as a
    local in another.
- The tree tags (`kLPValue`, `kNetVariableAssignment`, `kForInitialization`, ...) are Verible
  internals, checked on the pinned Verible `v0.0-4296-g0f262651`. A new pin may rename them;
  `node out/test/test_alwaysBody.js` would show it.
- Every `add*Always` call in `ts/src/` and `ts/test/` at `3076efa` (on `main` `355be80`, with
  AFIFO, CDCSynchronizer and GrayPointer) passes the checks. tssv-noc doesn't call these builders.
- Lint covers raw SV for three of the rules (IMPLICITSTATIC, COMBDLY, BLKSEQ). SEQ-6 and RST-2
  in raw SV are left to review, until #166.
