What the branch does:

- `ts/src/core/AlwaysBody.ts` (new) reads an always block's body at statement level. It blanks
  comments and strings, splits at each `;` outside brackets, and strips the control flow in front
  of a statement (`if (...)`, `for (...)`, `case (...)`, `begin`/`end` with labels, `else`, case
  labels, `always_ff @(...)`). It also finds the branch an `if (<reset active>)` selects. It isn't
  a parser.
- `ts/src/core/Base.ts`: the builders throw on a body that breaks a rule, and each error message
  names the rule.
  - COMB-3: `addCombAlways` rejects a nonblocking assignment. `<=` as a comparison is accepted.
  - COMB-2: `addCombAlways`, `addSequentialAlways` and `addLatchAlways` reject a local declared
    with an initializer that isn't `automatic`. It is an error, not a warning (decision on #149).
  - SEQ-1: `addSequentialAlways` rejects `=`, `+=`, `++` and the like to anything the block
    doesn't declare. Its locals and `for` loop variables are allowed.
  - SEQ-6: `addSequentialAlways` rejects a reset branch that reads a port or a non-constant
    signal. `addRegister` rejects a `resetVal` that isn't a `bigint`, at run time.
  - RST-2: `addRegister` and `addSequentialAlways` reject a reset whose kind (`isReset`) differs
    from the module's first one.
  - The three always builders had no JSDoc; they have it now. `addRegister`'s JSDoc mentions
    SEQ-6 and RST-2.

## Assumptions

- The body reader errs towards accepting. It misses some violations, and doesn't reject valid
  code. These cases aren't checked:
  - A case label with parentheses or a range, such as `(A | B):` or `inside {[0:3]}:`. Its
    statement isn't read, so it isn't checked.
  - A reset branch written another way: in an `else`, in a `case`, or with a condition other
    than `!rst`, `~rst`, `rst == 1'b0` (active-low), `rst` or `rst == 1'b1` (active-high).
    SEQ-6 doesn't see it.
- One known case where it rejects too much: in `addSequentialAlways`, a blocking assignment to a
  concatenation, `{a, b} = ...`, is rejected even when `a` and `b` are both locals. This is
  because `targetName()` doesn't take a concatenation apart. No existing code does this.
- Lint covers raw SV for three of the rules (IMPLICITSTATIC, COMBDLY, BLKSEQ). SEQ-6 and RST-2
  in raw SV are left to review.
- All 29 `add*Always` calls in `ts/src/` and `ts/test/` at `75f2ad7` pass the new checks. The
  three modules from PR #165 pass too (trial merge, 2026-10-15). Code added to `main` later
  hasn't been checked.
