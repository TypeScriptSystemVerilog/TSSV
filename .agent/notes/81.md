## Assumptions

- The rule is per byte, not per field. A field across a byte boundary takes only its strobed
  bytes. The issue stated this reading, and the human didn't object.
- A write with no strobe set still counts as a write. A register keeps its value, and a `WO`'s
  `<R>_we` stays low. A `RAM` still gets the request, with `WSTRB` 0.
- The top warning in `registers.md` ("the register-type table ... not what the type names
  suggest") is from before #80. #81 only removed "write strobes" from it. The PR's Notes say so.
- `APB_to_Memory` maps `PSTRB` to `WSTRB` unchanged. APB4's `PSTRB` is `DATA_WIDTH / 8`, so the
  widths now match at any data width. Before, they matched only when the data and address widths
  were equal. It still lints and passes `apb_to_memory_sim`.

## Dead ends

- **One block-wide byte mask signal** (`WSTRB` expanded to `wordSize` bits): its upper bits are
  unused, and fail `-Wall`, in a block whose registers are all narrower than the word.
  `strobedWrite()` instead references only the lanes each register or field covers.
- **Indexing a 1-bit field** (`X[0:0]`) is illegal for a scalar. `strobedWrite()` uses the signal
  whole when one lane covers all of it.
