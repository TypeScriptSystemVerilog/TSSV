## Assumptions

- The spec's throughput table and latency bounds come from a Python cycle model that isn't
  committed. The testbench checks the latency bounds as assertions, and the `depth = 8` row at
  the 10/11 ns clock pair. The other rows of the throughput table are model-only.
- Reviewers will accept the 144 baseline entries in `generated-baseline.json` (commit 34f3a3b).
  They are only the two LINT-3 findings for TSSV's blanket `lint_off WIDTH`, two per new file,
  as TwoClockRegFile's PR added. The baseline README says new findings should be fixed rather
  than baselined; this one can only be fixed in the emitter (#147).
- The testbenches' 0.3 ns phase offset keeps the two clocks' edges from coinciding outside the
  diagram replays. All three testbenches rely on that.

## Dead ends

- `GrayPointer` with Gray-coded outputs. One of the AFIFO's two instances then had an output it
  never read. That fails `-Wall` (UNUSEDSIGNAL), and MOD-6 forbids leaving it unconnected. Its
  outputs are now binary only.
- Holding each changed bit of `sync_0` at random, as a metastability model. With a faster
  source clock, it can produce a value the input never held. The right model loads either `d`
  or the `d` from the previous edge (`CDCSynchronizer` spec, Assertions).
- Proving `a_rd_latency` with a "never load a head into an empty FIFO" mutation. `empty` still
  falls, so latency doesn't change; only the reference model catches it. A synchronizer two
  flops too long does fire `a_rd_latency`.
- Importing `tssv/lib/...` from a script outside the package. It doesn't resolve. Require
  `<worktree>/out/src/modules/<Module>/index.js` by absolute path instead.
