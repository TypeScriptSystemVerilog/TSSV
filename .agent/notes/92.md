## Assumptions
- GitHub rebases the PRs above a merged PR in a GitHub stack, and retargets PRs to `main` when
  a merged branch is auto-deleted. Both come from tssv-noc's runbook and GitHub's docs; neither
  was tested here.
- A child stacked by base only on a parent whose base is `main` never sees the parent rebased,
  because GitHub only rebases branches above a PR that merges. This is reasoning, not a test.
