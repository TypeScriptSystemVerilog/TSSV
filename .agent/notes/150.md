## Assumptions

- `undefOnWrite` makes a conflicting read's whole word undefined, whatever the write's mask,
  following the spec's wording. The old code tried lane by lane. The reviewer may prefer
  lane-wise; `tb_SRAM.sv`'s `written` test would then have to look at the mask too.
- Rejecting `depth < 2` breaks no caller: SFIFO skips the SRAM at depth 1, and `cpu_convert`
  depths come from real macros.

## Dead ends

- Verilator is two-state, so `tb_SRAM.sv` can't check that a conflict reads X. It tracks
  defined bits instead and fails a run that never hits the case.
- Linting `SFIFO_*/` directories rather than `*.f` breaks in CI: `check:rtl-style` runs first,
  and the TSSV guide's TEST-1 example writes `SFIFO_8_4_true_false_false/` as one file.
