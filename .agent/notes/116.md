## Assumptions

- **`READY` is tied high, not driven by the last-hit window.** The issue says `RegisterBlock` drives
  `READY` from the target of the last access. A window's `<R>_ready` is an output the block
  registers from its own `regs.READY`, and it resets low. Routing it made an APB read of a window
  after reset hang once `PREADY` followed `READY`. #80 gives windows a real ready input. The human
  has not confirmed this yet.
- No tssv-noc code uses `Memory`, `RegisterBlock` or `APB_to_Memory` (grep, 2026-10-09).
- `FIR` wraps a `RegisterBlock` and exposes its `regs` port. It is not a separate Memory master or
  slave.
