## Assumptions

- Requests never go back to back. The master BFM leaves at least one idle cycle between
  accesses. The `Memory` contract's "raises WE or RE for exactly one cycle" reads as a one-cycle
  pulse per request; WE or RE high in consecutive cycles is not tested.
- An unaligned address never matches a register: `decodeExpr()` compares all of `regs.ADDR`
  (`registers.md` §2). An unaligned address inside a window reaches the slave, which ignores the
  byte offset. The probes rely on both.
- The read model takes a window first, then the first non-`WO` register in `addrMap` order at
  exactly the address. That matches the hardware as long as no register lies inside a window,
  which no test definition does.

## Dead ends

- **Unrolled checks with no SV tasks**: one read was about 5 SV lines. The sweeps (about 400
  reads each) would have made a 10k-line testbench. `read_check()`/`write_check()` keep each
  step to one line.
- **A two-line replacement in the mutation script**: `read` with `IFS='|'` reads one line only,
  so the second line was dropped and a different mutant was planted. Use one-line replacements.
