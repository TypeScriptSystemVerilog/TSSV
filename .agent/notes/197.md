## Assumptions
- **The user's decision, 2026-10-30: PatternMemory reads synchronously**, the block-RAM form. The
  tables therefore fetch one row ahead, with a priming cycle after reset. Row 0 lasts two cycles,
  so the PASS lines say 14 and 65 cycles, up from 13 and 64. Why it can't be avoided without
  `rst_b` as data (lint SYNCASYNCNET) is in `testbench.md`, "Cycle tables and their timing".
- `firstRow` stays a structural parameter of VectorChecker. It gates checking in the RTL and
  offsets `err_row`, and isn't written into the pattern file. Nothing used it as of 2026-11-02.
- Verilator 5.052 `--lint-only -Wall`, with and without `--no-timing`, accepts a memory that only
  `$readmemh` writes (checked 2026-11-02).
- Diagram 1 in `testbench.md` was rendered locally with mermaid-cli 11.12.0 and looks right. The
  second `$readmemh` label sits over the harness's title text. It is still readable, and GitHub's
  rendering wasn't checked.

## Dead ends
- In PatternMemory, reading the whole word into a register (`rd_word <= mem[rd_addr]`) and then
  slicing the fields out of it. Lint `-Wall` reported UNUSEDSIGNAL on the pad bits of `rd_word`.
  Each field is now registered straight from `mem[rd_addr][hi:lo]`.
- Naming the player's and checker's memory instance `mem`. Lint reported VARHIDDEN, because the
  instance hid the memory's own array `mem`. The instance is now `pattern`, so the manifest's
  memory paths are `h.play.pattern`, `h.chk.pattern` and `h.chk_<tag>.pattern`.
- `npx eslint <file>.mjs` fails with "Parsing error: The keyword 'const' is reserved". ESLint isn't
  set up for `.mjs` files, and `npx eslint .` doesn't lint them, so pass only `.ts` files.
- With node:test, a bare `test(...)` fails ESLint's no-floating-promises rule. Write `void test(...)`.
